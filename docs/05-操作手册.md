# 05 · 操作手册 —— 照着做就能复现

> 本手册是**可勾选的复现清单**，每步都有验证方式。
> 原理和详细解释见 [01 板子](01-板子固件篇.md) / [02 Host](02-Host配置篇.md) / [03 云端](03-云端配置篇.md)。

---

## 〇、装备清单

- [ ] Windows 11 电脑（建议 16GB 内存、E 盘留 10GB）
- [ ] EasyInput V2 键盘 + USB **数据线**（不是纯充电线）
- [ ] 2.4GHz Wi-Fi（板子只支持 2.4G），电脑与板子同网段
- [ ] WSL2 + Ubuntu
- [ ] Rust 工具链（`cargo --version`）
- [ ] Codex CLI（`codex --version`）
- [ ] 阿里云百炼 **API Key**（北京区）
- [ ] （烧固件才需要）ESP-IDF + usbipd-win

---

## 一、Windows 侧准备

- [ ] **环境自检**
  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\windows\setup-wsl.ps1
  ```
  确认：WSL 在跑、能识别板子 USB、内存磁盘够。

- [ ] **防 WSL 被回收** —— 在 `%USERPROFILE%\.wslconfig` 写：
  ```ini
  [wsl2]
  instanceIdleTimeout=-1
  ```
- [ ] **保活脚本** —— 把 `scripts\windows\keepalive.vbs` 放进启动目录
  （`Win+R` → `shell:startup`）。

---

## 二、WSL 侧：编译并启动 Host

- [ ] **打补丁 + 编译**
  ```bash
  cd <你的仓库路径>          # 例如 ~/codex-keyboard-win
  bash scripts/wsl/apply-patches.sh
  ```
  验证：出现 `target/release/easy-codex-host`。

- [ ] **配置 API Key**（仓库外）
  ```bash
  sudo tee -a /etc/environment >/dev/null <<'EOF'
  QWEN_API_KEY=<在此填你的 DashScope key>
  EASY_CODEX_CLI=/usr/local/bin/codex
  EOF
  ```

- [ ] **装服务**
  ```bash
  bash scripts/wsl/install-service.sh
  ```
  验证：`systemctl is-active easy-codex-host` 输出 `active`；
  `ss -lunp | grep 17333` 有输出。

- [ ] **配置 Codex 连千问** —— `~/.codex/config.toml` 里写：
  ```toml
  model = "qwen3-max"
  model_provider = "qwen"
  [model_providers.qwen]
  base_url = "https://dashscope.aliyuncs.com/compatible-mode/v1"
  env_key = "QWEN_API_KEY"
  ```
  验证：`codex exec --json --skip-git-repo-check "你好"` 返回 JSON。

## 三、板子侧：配网 + 绑槽位

- [ ] **配网**（板子插 USB，把 Wi-Fi 和 Host 地址写进去）
  ```bash
  host_ip=$(hostname -I | awk '{print $1}')
  ./target/release/easy-codex-host provision-lan "你的WiFi名" "$host_ip" 17333
  ```
  验证：板子灯条有反应；`bash scripts/wsl/doctor.sh` 能看到心跳。

- [ ] **绑四个槽位**
  ```bash
  bash scripts/wsl/bind-slots.sh
  ```
  验证：`./target/release/easy-codex-host health` 显示 4 个槽已绑定。

## 四、（可选）烧录固件

> 只在需要"任务电台"功能时做。官方固件没有电台功能。

- [ ] **共享 USB 给 WSL**
  ```bash
  usbipd list                      # 找 ESP32 BUSID
  usbipd attach --wsl --busid 1-1
  ```
- [ ] **板子进下载模式**：开机状态**短按一次 BOOT 松开**（不是按住！）
- [ ] **编译 + 烧录**
  ```bash
  IDF_DIR=$HOME/esp/esp-idf bash scripts/wsl/flash-firmware.sh
  # 装到别处就改 IDF_DIR（也可不传，脚本默认 $HOME/esp/esp-idf）
  ```
- [ ] **闭环验证**（烧录 exit 0 不算成功）
  ```bash
  sudo timeout 10 tcpdump -nn -i any udp port 17333
  ```
  看到「板子 → Host 80 字节」和「Host → 板子 32 字节」成对往返 = 成功。

## 五、验收清单（核心）

| # | 操作 | 预期 | 勾选 |
|---|---|---|---|
| 1 | 按住 **S1** 说"1+1 等于几"，松手 | 几秒后**第 5 颗灯变黄** | [ ] |
| 2 | 等 30~60 秒 | 第 5 颗灯回绿；**第 1 颗灯亮** | [ ] |
| 3 | 按 **S5** | 听到语音答复；播完第 1 颗灯灭 | [ ] |
| 4 | 按住 S1 连说两条 | 两条都执行（可能合并成一条播报）| [ ] |
| 5 | 播放中按住任意语音键 | 播放立刻让位（灯不灭）| [ ] |
| 6 | 旋钮转到某档 → 停 1 秒 → 断电重启 | 档位保持不变 | [ ] |
| 7 | 按 S2/S3/S4 说话、按 S6/S7/S8 播放 | 四个槽独立可用 | [ ] |

## 六、排障速查

| 现象 | 第一件事 | 常见原因 |
|---|---|---|
| 灯永不变黄 | `sudo tcpdump -nn -i any udp port 17333` | **端口不匹配**（Host vs 板子）|
| 按键完全没反应 | `systemctl is-active easy-codex-host` | Host 没跑（WSL 被回收）|
| 板子突然不理人 | 是不是拔了 USB 闲置 30 分钟 | 电池供电会**深睡**，按键唤醒 |
| 按 S5 没声音 | 查 `summary_ledger.state` | 卡在 `generating`（僵尸）→ 跑清理 |
| 任务 0 秒失败 | 看 rollout 的 error | 缺 `QWEN_API_KEY` / 会话坏了 |
| 说长句被吃掉 | 看有没有 `lan_voice_rejected` | 序号缺口（已修，仍出现则查 Wi-Fi）|
| 宿主测试失败 | 先确认是不是**原版也失败** | 见 `04-总结与踩坑.md` 第 11/12 条 |

一键诊断：
```bash
bash scripts/wsl/doctor.sh
```

## 八、如果你想改点什么

| 想改 | 去哪改 | 注意 |
|---|---|---|
| 端口 | `ECI_LAN_AUDIO_PORT`（service 文件 + 板子配网）| **两边必须一致** |
| 总结用的模型 | `~/.codex/config.toml` + `spark_runner.rs` 的 `SPARK_MODEL` | 改代码要重编译 |
| AI 模型（ASR/TTS）| `dashscope.rs` 顶部的常量 | 硬编码，要重编译 |
| Codex 工作目录 | 绑槽位时 `ECI_CODEX_CWD` | 目录越小越快 |
| 固件行为 | `firmware/` + 重新烧录 | 改固件必须重烧 |
