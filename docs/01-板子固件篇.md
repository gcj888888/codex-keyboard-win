# 01 · 板子（固件）篇 —— 固件怎么烧、怎么工作

> 本篇基于我们**实际跑通**的经验编写，不是原项目文档的转述。

## 一、硬件是什么

| 项 | 值 | 来源 |
|---|---|---|
| 主控 | **ESP32-S3R8** | `esptool chip_id` 实测 |
| 内存 | 8MB PSRAM（封装内）+ 16MB Flash | 实测启动日志 |
| 芯片特征 | QFN56 / rev v0.2 / 40MHz 晶振 / USB-Serial-JTAG | 实测 |
| 板子 | EasyInput V2（8 键 / 5 灯 / 旋钮 / 麦克风 / 扬声器 / 电池）| `board_pins.h` |
| MAC | 每块不同（例：`xx:xx:xx:xx:xx:xx`，实际以你板子为准）| 验身时读取 |

### 引脚表（`firmware/components/keyboard/include/keyboard/board_pins.h`）

| 功能 | GPIO |
|---|---|
| 8 个按键 S1–S8 | 2 / 47 / 38 / 41 / 1 / 6 / 7 / 48 |
| 旋钮 A / B / 按下 | 17 / 16 / 18（方向系数 -1）|
| WS2812 灯条（5 颗） | 12 |
| 麦克风 I2S | BCLK 9 / WS 10 / DIN 11 |
| 扬声器 I2S | WS 13 / BCLK 14 / DOUT 15 |
| 电池使能 / 采样 | 5 / 4 |
| 外部供电检测 | 40（低有效）|
| 充电状态 | 39（高=充电中）|
| 外设电源开关 | 8 |
| 深睡唤醒 | 21 |
| USB D- / D+ / BOOT | 19 / 20 / 0 |

**功放**：MAX98357A（代码里有 `max98357a_supports_lrclk()`）。

### Flash 分区（实测）

```
0x000000     20 KB    bootloader
0x008000      3 KB    partition-table
0x009000     24 KB    nvs          ← Wi-Fi 密码 / Host 地址 / 音量档位 / 音频密钥
0x00f000      4 KB    phy_init     ← RF 校准
0x010000      3 MB    factory      ← 应用（实测约 2.16 MB，占 69%）
0x310000    576 KB    sound_a      ← 音效库 A（出厂为空，可 OTA 更新）
0x3A0000    576 KB    sound_b      ← 音效库 B（A/B 双槽）
```

> ⚠️ **这就是"绝不能 erase_flash"的原因**：`nvs` 里有你的 Wi-Fi 密码；
> `sound_a/b` 是板载音效区。擦全片 → Wi-Fi 要重配、音效丢失。

## 二、固件从哪来

```
原版固件（上游 firmware/）
   └─ + 我们的 2 处改动（patches/02-firmware-fixes.patch）
        1) 录音队列 64 帧 → 256 帧（1.28 秒 → 5.12 秒缓冲）
        2) 新增「序号缺口 ≤10 帧不再作废整次录音」
```

**为什么改这两处**：Wi-Fi 一抖动，录音采集队列就溢出 → 丢帧 → 序号出现缺口 →
固件原本**立刻作废整句话**（表现：你说了一长句，Host 只收到半句）。
改后小额缺口交给 Host 补静音，不再整句丢弃。

## 三、固件怎么编译（这一步我们踩过大坑）

### ✅ 正确做法：在 WSL 里编译

```bash
export IDF_PATH=/root/esp-idf-local          # ESP-IDF 5.5.5 装在这里
export IDF_TOOLS_PATH=/root/.espressif
export PATH="/root/.espressif/python_env/idf5.5_py3.14_env/bin:$PATH"
export PATH="$(ls -d /root/.espressif/tools/xtensa-esp-elf/*/xtensa-esp-elf/bin | head -1):$PATH"

cd firmware
python "$IDF_PATH/tools/idf.py" build
```

产物：`firmware/build/easy_codex_input.bin`（约 2.16MB）。

### ❌ 我们走过的弯路

1. **以为要用 Windows 的 ESP-IDF** —— 在 `C:\esp\v5.5.5` 上折腾了 5 种办法全失败。
   **真相：WSL 里早就有一套完整可用的 ESP-IDF**，原作者的构建产物就在里面。
   → 教训：**先找现成的路（看原作者的 build 日志/产物），别凭想象造方案。**
2. **`source export.sh` 失败** —— 报 `tool riscv32-esp-elf-gdb has no installed versions`。
   那个工具是给 **RISC-V 芯片**（ESP32-C 系列）用的，我们 S3 是 XTensa，根本不需要。
   `export.sh` 做的是**全量检查**，缺一个无关工具就整体失败 → **手动配 PATH 绕过它**。
3. **cmake 报 `head-ref` 缺失** —— 因为仓库是"有 `.git` 但没有 commit"的空仓库，
   `git_describe` 生成不了 `head-ref`。**解决：建一个空 commit**：
   ```bash
   git -c user.email=x@x -c user.name=x commit --allow-empty -m "init"
   ```

### 一键脚本

```bash
IDF_DIR=/root/esp-idf-local bash scripts/wsl/flash-firmware.sh
```

## 四、固件怎么烧录

### 步骤

```bash
# 1) Windows 侧：把板子 USB 共享给 WSL（烧录必须）
usbipd list                          # 找 ESP32 的 BUSID，例如 1-1
usbipd attach --wsl --busid 1-1      # WSL 里会出现 /dev/ttyACM0

# 2) 板子进下载模式：开机状态「短按一次 BOOT 松开」
#    （不是按住！板上没有 RESET 键）

# 3) 验身：先读芯片型号和 MAC，确认烧对设备
esptool.py --chip esp32s3 -p /dev/ttyACM0 chip_id

# 4) 烧录
bash scripts/wsl/flash-firmware.sh
```

### 烧录参数（编译输出给的权威值）

```
esptool --chip esp32s3 -p /dev/ttyACM0 -b 460800 \
  --before default_reset --after hard_reset write_flash \
  --flash_mode dio --flash_size 16MB --flash_freq 80m \
  0x0     bootloader/bootloader.bin \
  0x8000  partition_table/partition-table.bin \
  0x10000 easy_codex_input.bin
```

**只写这 3 个区**，`nvs` 和音效区一个字节都不碰。

### 烧录后的闭环验证（重要）

**烧录 exit 0 ≠ 新固件在跑**。必须验证：

```bash
# 抓包看板子是否恢复发心跳（80 字节包 + Host 回 32 字节）
sudo timeout 10 tcpdump -nn -i any udp port 17333
```

看到成对往返：
```
192.168.x.x.49505 > 192.168.x.x.17333: UDP, length 80   ← 板子发
192.168.x.x.17333 > 192.168.x.x.49505: UDP, length 32   ← Host 回
```
= 新固件正常运行 ✅

## 五、固件内部怎么工作（我们读代码+实测搞清的）

### 按键 → 录音 → 发包

```
按键按下（S1-S4 = 语音键）
  → 固件录音：16kHz / 16bit / 单声道，每 20ms 一帧（320 采样 = 640 字节）
  → 每帧加 32 字节头 + 16 字节 HMAC-SHA256 签名 = 688 字节
  → UDP 发给 Host 的 17333 端口（走 Wi-Fi）
  → 松手后发结束帧（EIAE）
```

**关键常量**（实读源码）：
| 常量 | 值 | 含义 |
|---|---|---|
| `kAudioCaptureQueueFrames` | **256**（我们改的，原 64）| 录音缓冲 ≈5.12 秒 |
| `kAudioMaxToleratedGapFrames` | **10**（我们新增）| 序号缺口容忍 200ms |
| 采样率 | 16000 Hz | 上行 |
| 帧长 | 20 ms（320 采样 / 640 字节）| |

### 心跳 → 灯

```
固件每 2 秒（空闲时 4 秒）发 80 字节心跳（EIHB）给 Host
  → Host 回 32 字节（EIMB），里面带：未读槽位数、运行任务数、coverage
  → 固件据此更新 5 颗灯
```

**灯语义**：左起 1-4 灯 = 各槽未听总结（越亮越多）；第 5 颗 = 运行任务数（0绿/1黄/2橙/3紫/4红）。

> ⚠️ **灯只由心跳更新** —— 这是"按 S1 后灯要等几秒才变黄"的原因：
> ① 松手时 Host 还在做 ASR（真相源还是 0）② 任务真的启动了 ③ 等下一轮心跳
> ④ 灯才变黄。这是"真相源不在板子上"的必然延迟（设计如此，非 bug）。

### 播放

```
按 S5-S8 → 发播放请求（EIPR）
  → Host 回 EIPB → 板子回 EIPA
  → Host 发 EIPD 音频流（AES-256-GCM 加密，IMA-ADPCM 压缩约 4:1）
  → 板子解密 + 解压 + 48kHz 播放（缓冲 24KB 后出声）
  → 播完发 EIPF，Host 标记为「已听」
```

### 音量

旋钮 → 立即生效（10 档）→ **停止转动 1 秒后**写入 NVS `spk_vol_v1`。
（那 1 秒是防抖，避免每个脉冲都擦写 Flash —— 所以"停 1 秒再断电"档位才保得住。）

### 配网

Host 通过 **USB HID** 把「Wi-Fi SSID + 密码 + Host IP + 端口 + 音频密钥」下发给板子 → 存 NVS。
